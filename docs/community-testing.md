# Experimental MiSTer Main testing

The `-x15` build changes MiSTer Main, the ARM application. It preserves official FPGA cores and Linux. The fork includes AI-assisted development and is not an official MiSTer-devel release. Compilation and host regressions do not establish hardware compatibility.

## Prepare a recoverable test

Use a spare, working MiSTer card with the same official baseline you normally use. Keep your original card, working Main binary and configuration available so you can recover without relying on a network connection. Verify the candidate's SHA256 against its supplied manifest and record `SOURCE_COMMIT.txt`. Do not copy the example MiSTer.ini over your configured file.

Install only the candidate Main executable using the normal Main replacement procedure for your setup. Keep its accompanying source archive and license. Confirm the version includes `-x15` in the System Settings page before testing. No deployment or card writes are performed by the fork's CI.

## Record results

Record the exact source commit, board model, Linux version, core versions, display model and relevant INI settings. Report reproducible steps, observed and expected behavior, and whether the same steps fail with your working official Main. Share only logs you have checked for private information; no ROMs, paid unlock keys or credentials.

## Return to the working build

Restore your known-working Main or switch back to the original card, and verify the version and normal operation. The official updater may replace the experimental Main; record the version before any subsequent tests. Mark unavailable hardware combinations as untested.

## Scope of this candidate

The candidate restores VRR packet programming after HDMI reset, corrects ZIP browser comparisons and paths, offers a 12-hour clock, preserves expanded-name paging rows, and avoids unchanged ordinary-HDMI SPD requests. It corrects remap source selection, release ownership, F12 handoff, ordinary button skips and Advanced capture pairing protection. File handling preserves complete ZIP cache names, resolves eligible MGL F paths through sibling ZIPs, launches literal document paths, retains active metadata after initial open rejection, rejects incomplete MGL filenames without contaminating following actions, and rejects names and paths that cannot fit intact in the file-open APIs. Checked generic transfers stop failed host reads and distinguish incomplete loads. Screenshot workers own their save path before queuing, with a separate relative completion name. Other legacy path callers, generated-name truncation, the separate addon API and nested GAMEID ordering remain further work. No measured gameplay speedup, Linux driver repair, new FPGA feature or general stability guarantee is claimed. Performance work requires baseline measurements on actual hardware.

# Independent MiSTer Main development

This fork develops fixes and features for the MiSTer Main ARM software. It is an experimental, AI-assisted project owned by djjohnson13p, with no upstream pull requests planned. FPGA cores, the Linux image and Downloader remain separate projects.

The starting upstream revision is `2dd3662cccd45d54d3d383bf9f7d80f6f57e6d03`, fetched October 13, 2026. Development uses `independent/main`; `master` preserves the original fork baseline. The current candidate identifies itself with `-x12`; the earlier `-x1` through `-x11` candidates and their source commits remain available. `upstream-base.txt` records the accepted official baseline.

## Reviewed changes

| Change | Evidence and status |
| --- | --- |
| Restore VRR after HDMI initialization | [Upstream issue 1226](https://github.com/MiSTer-devel/Main_MiSTer/issues/1226). HDMI initialization clears packet enables; invalidate the cached VRR mode so the next mode setup restores the packets. Regression harness uses production video functions with simulated I2C. Physical display validation is pending. |
| Optional 12 hour Menu clock | [Upstream request 990](https://github.com/MiSTer-devel/Main_MiSTer/issues/990). Set `osd_clock_12h=1` in MiSTer.ini for AM/PM; the default stays 24 hour. Both formats fit the existing 32-column row. |
| Correct browser comparisons and ZIP folder paths | Duplicate parent entries now compare equivalent, as required by `std::sort`. Implicit ZIP folders require a full path prefix, so `outer/target` cannot falsely satisfy a request for root `target`. Real ZIP regressions preserve existing directory/ZIP ordering. |
| Preserve complete cached ZIP container names | A real archive with a 256-byte container path opened successfully, but the old 256-byte cached name had no terminator before a later C-string comparison. The cache now matches the full-path buffer capacity and always terminates its copied name. Real ZIP tests cover the boundary, complete names, reader reuse and existing case-insensitive comparison. The change adds 1,844 bytes of static cache storage. |
| Resolve missing MGL ROM paths through sibling ZIPs | [Request 665](https://github.com/MiSTer-devel/Main_MiSTer/issues/665). For an absent ordinary MGL F file, try the same-stem ZIP and select exactly one supported regular member with the same full extension, ignoring case. The member can have a different name or nested folders. Existing literal files take priority; explicit ZIP paths, manual selection, S image mounts, NOZIP and NeoGeo ROM sets retain their behavior. Ambiguous, malformed, unsupported and overlong candidates leave the original path unchanged. |
| Preserve files when paging onto an expanded name | With `lookahead=0` and `browse_expand=1`, an expanded destination at the bottom row could advance the rendered viewport past an unseen file. Forward paging now reserves one row for either the current or relevant destination expansion, without deducting twice. The last item retains its full step. Production paging and rendering tests cover both directions and 8/16-row layouts. |
| Avoid unchanged SPD writes during ordinary HDMI popups | Menu transitions only request SPD updates when Direct Video or Minimig RTG metadata contains OSD state. Host tracing shows 68 writes and two reads removed per ordinary-HDMI popup entry/exit with default SPD settings. Forced refresh, resolution changes, HDMI reset and DV/RTG updates remain covered. Hardware latency is unmeasured. |
| Choose the remap source on a fresh press | [1245](https://github.com/MiSTer-devel/Main_MiSTer/issues/1245) and the device-selection portion of [1305](https://github.com/MiSTer-devel/Main_MiSTer/issues/1305). A delayed release from the device used to open Button/Key remap could select that device before any source press. The dialog now waits for a new press while no source is selected; keyboard output capture still supports another device; release ownership is covered below. |
| Show the selected remap source | [898](https://github.com/MiSTer-devel/Main_MiSTer/issues/898). The dialog identifies the source before clearing or finishing, and prompts for a source while none is selected. Normal mapping identity rules still apply: devices configured to share a mapping continue to share its saved file. |
| Complete remap capture only for its accepted presses | After a source was chosen, an unrelated release could advance input capture, save output prematurely, or become an Escape clear command. Capture now matches releases to the normalized code and effective device of a fresh press accepted in that phase. First-member chord completion, keyboard output from another device and genuine Menu controls remain supported. Transient tracking also retains accepted members displaced by the four stored chord slots; the mapping file format is unchanged. |
| Freeze completed remap edits and commands | Queued input arriving before the UI consumes a completed Advanced edit or accepted Clear/Finish could append to its captured codes or erase Clear. A transient completion flag now stops further capture while retaining combo bookkeeping. A new capture resets that flag. Menu-core Clear and Advanced remain disabled, and their keys cannot freeze capture. |
| Preserve F12 Advanced handoff | A fast F12 release could cancel Advanced before the UI saw it; a held release after handoff could close Advanced again through the normal menu queue. A fresh F12 press now records a pending command and its effective device/normalized key. Only the explicit successful Advanced handoff retains ownership of that held release. Repeats cannot invent a command, unrelated events retain normal handling, and input-inventory rebuilds invalidate stale ownership. The gamepad OK-hold timer remains supported. |
| Preserve literal document launch paths | The launch script split directory names containing spaces, evaluated shell syntax in selected filenames and exceeded its 2,048-byte buffer for a valid 1,021-byte path. The script now uses dynamically sized strings and POSIX literal quoting for the file and its working directory. Extension selection uses the basename safely. PDF, TXT and Markdown commands, the Markdown pipeline, terminal environment, child launch and exit status retain their behavior. |
| Complete ordinary button skips without retaining a pending press | [1008](https://github.com/MiSTer-devel/Main_MiSTer/issues/1008). A two-button Menu combo could leave its first member in the skipped direction and retain a pending-key latch, preventing the next assignment. A queued Space release or repeat could also erase a newer capture. Accepted skips now discard pending capture at the existing skip/advance point and clear the selected half of slot zero too. Unaccepted Space events preserve capture; alternate halves, negative-axis steps, placeholder skips and keyboard/Advanced remapping retain their behavior. |
| Preserve active metadata after an initial file-open rejection | A missing generic F file changed the screenshot basename, selected a different manual and reset enabled cheats despite leaving the previous game and CRC active. Screenshot/docs/cheats now update only after the transfer passes its initial rejection guards. Stored-name suppression and specialized N64/C64/Atari timing remain intact. |
| Keep physical Menu Bluetooth pairing out of Advanced capture | Holding the physical Menu button for three seconds could open Bluetooth while count-one Advanced input/output capture remained active. Its completion consumer then stopped running and captured USB keys could not dismiss the popup. The existing pairing guard now also excludes that exact capture state; normal pairing on the Advanced list and inactive mask screens remains available. |
| Retain complete MGL filenames and clean rejected action slots | A decoded XML path beyond 1,023 bytes was shortened and marked valid, allowing a different existing ZIP member at that prefix to load. The parser now rejects that action, including either order of duplicate path attributes. Each recognized file/reset starts with an empty slot, so rejected fields cannot become the following reset's default hold. Fitting paths and six accepted actions retain their behavior. |

Fresh Enter, Esc and F12 command presses before source selection retain their existing behavior: they choose the command device for Finish, Clear or Advanced. Pending releases and repeats do not choose a source. A release of the first accepted chord member still completes that phase; unmatched releases and releases left over from the previous phase do not. Matching uses the effective device after binding and keyboard normalization, before a genuine Menu release can become Escape.

## Validation and next work

MGL fallback uses the resolved archive/member path consistently for loading, extension index, logging, docs, cheats and generated save paths, just as manual ZIP selection does. If `Game.gba` resolves to `Game.zip/Renamed.gba`, save and savestate names follow `Renamed`; existing `Game` saves are not renamed or migrated. Archives with several matching members require an explicit `zip/member` path. A clipped HomeDir-plus-item path is skipped before load side effects. Generic F metadata after an initial open rejection is corrected below. Later transfer errors, numeric XML attribute validation and downstream specialized path joins remain separate existing limitations.

The MGL regression runs intact production file APIs, bundled miniz and both generic F/S selected cases with temporary synthetic fixtures and hardware/persistence spies. It passes 164 checks; pre-feature x5 fails 51, including an actual missing-file open despite the sibling ZIP. This covers original-file priority, renamed/nested members, full filename retrieval, extension/index preservation, ambiguity, unsupported/encrypted entries, byte bounds, descriptor cleanup, writable-image exclusions and path consumers.

The document regression runs the production script builder and complete selected case with synthetic paths, video/persistence/process spies and actual Bash command parsing and dispatch. All 774 checks across 83 path fixtures pass; pre-fix x7 fails 134. It covers quotes, shell characters, Unicode, newline directories, 1,021/1,023-byte paths, complete script saves, viewer arguments, environment, exit status and the real Markdown pipe. Historical writes are measured and diagnostically capped to avoid executing a buffer overflow. A synthetic shared-path overwrite checks defensive ownership before video calls; it does not establish a real video-call overwrite. Viewer execution and hardware testing remain pending.

The ordinary mapping regression runs the complete production mapping branch and actual hardware Skip dispatcher in 28 fresh processes. It passes 141 focused checks, 507 inherited fixture/safety checks and the existing 801 event checks. Both x8 and the official baseline fail the same 30 focused checks; the official source's 83 failures for earlier fork improvements are recorded separately. Controls cover either Menu-combo release order, slots zero/four, base/alternate halves, delayed Space release/repeat, selected-device retention, automatic placeholders, Menu-core definition/calibration and legacy keyboard remapping. Peripheral hardware and persistence are fixtures; physical testing remains pending.

The file-load metadata regression runs the actual generic transfer, F/S selected cases, file/ZIP/miniz backend, filename helper, manual lookup and cheat initialization with synthetic data and peripheral spies. All 251 checks pass; x8 and x9 fail the same 61 preservation assertions. Missing files, missing ZIP members and rejected archives retain the active screenshot/manual/enabled-cheat state and CRC. Accepted raw/ZIP/fallback files, stored names, valid empty files, specialized loaders, writable S images, PCE preprocessing and addons retain their policies. The transfer's nonzero return means it reached its existing completion path; it does not guarantee every read or hardware delivery succeeded. Later read, mapped-memory and Goomba prerequisite errors remain outside this fix.

The Advanced Bluetooth guard regression executes the actual physical Menu key reader, UI decode, Advanced capture/finish/clear cases and no-adapter Bluetooth popup with real input capture and normal keyboard dispatch. It passes 96 focused and 70 fixture checks in 13 fresh processes; x9 and official source fail the same 34 focused checks. Controls cover pending/held input/output capture, completion and opposite-half retention, F12 save identity, fresh pairing after completion, popup dismissal, Escape/controller Clear, ordinary protected remapping, inactive mask screens, short Menu presses and Scripts Backspace. Existing 182 handoff and 801 event checks pass. A simulated clock and no-adapter query spy exercise software behavior; physical Menu and Bluetooth validation remain pending.

The MGL attribute regression executes the real sxmlc reader, callback/parser/getter, post-core script scheduling decision, file/ZIP transfer and generic F/S selected cases. All 114 checks pass; x11 fails 30 and official source fails 34, including four additional side-effect failures covered by earlier fork protections. It proves a 1,033-byte requested member previously became a different existing 1,023-byte member and loaded 31 synthetic bytes. Fitting paths, UTF8, XML entities, duplicate attributes, rejected-slot recovery, default reset hold, six-action capacity, following F loads and writable S dispatch are covered. Boundary paths use short components to avoid a separately identified unchecked file-API basename copy; no historical process crash is counted as this regression's proof. Numeric attributes, delegated loaders, downstream specialized joins and physical operation remain outside this correction.

The pristine upstream and earlier x1 fork both compile with Arm GCC 10.2.1, using identical settings and zero ARM warning diagnostics. The x1 candidate is 1,288,228 bytes with SHA256 `6a36103753d9bd9301b42e335328da48bb75c5a9ce8f9acebdcbe0cec0a51e4a`; the baseline is 1,288,236 bytes. Binary size differences are not performance results. Each candidate carries its own build receipt and checksums.

Host coverage includes nine VRR cases, real ZIP and comparator tests, Menu clock/layout tests, 27 SPD cases, 1,765 paging transitions, eight isolated Git review tests, 801 remap event checks and 182 remap UI checks. The combined event/keyboard/menu handoff suite repeats the 801 event checks and adds 182 focused checks in 39 fresh processes; x6 fails 27 event and 41 focused checks. Its production paths include keyboard normalization, modifier handling, menu queue/debounce, actual remap handoff and input-inventory reset hooks. The earlier 516-check suite fails 30 assertions against x3 and 54 against the official baseline. The long ZIP cache checks fail two assertions against x4; a separate real-ZIP probe confirms the same defect in official source. Identical video and browser regressions also fail against their pre-fix sources. Corrected ZIP-cache tests compile without the old host `strncpy` warning. Independent review also caught and corrected clipping of the combined Main/OS version row.

The CI workflow pins the Linux Arm compiler archive by SHA256 and builds the same pristine baseline before the fork. It runs the host regressions and saves an experimental candidate, source archive, commit identifier, hashes and logs. [The first hosted run passed](https://github.com/djjohnson13p/Main_MiSTer/actions/runs/38485276379) for source commit `7885a7ed62fc6fe1b55afd3904e851acc5433c0e`.

The [community test procedure](community-testing.md) covers recovery, Menu navigation, paging, Info popups, remap source choice and clearing, controller input, core loading, HDMI reconnect and both clock modes. VRR requires compatible FreeSync and VESA displays. Physical device testing and community outreach are pending. Further software work should prioritize another reproducible defect, while comparing new official changes under the policy below.

Use the [upstream review policy](upstream-review.md) to monitor official changes, compare overlapping fixes, and integrate useful upstream work after validation. A quiet daily heartbeat and an explicit review ledger keep that work separate from untested assumptions.
